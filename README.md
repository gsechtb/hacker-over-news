# Hacker Over News

A cybersecurity blog and news site: statically generated with Next.js, MDX blog posts, client-side search, tag browsing, an RSS feed, and an auto-refreshing news feed aggregated from established security publications via a scheduled GitHub Action. Deploys to GitHub Pages for free, with no backend server required.

## Stack

- **Next.js (App Router)** with `output: "export"` — fully static, deployable anywhere.
- **MDX** blog posts (`content/posts/*.mdx`), parsed with `gray-matter` and rendered with `next-mdx-remote`.
- **Tailwind CSS v4** + `@tailwindcss/typography` for the design system and prose styling.
- **Fuse.js** for client-side fuzzy search over a generated search index.
- **`feed`** for RSS generation, plus `app/sitemap.ts` / `app/robots.ts` for SEO.
- A small Node script (`scripts/fetch-news.mjs`) that pulls RSS from several cybersecurity news outlets and writes `data/news.json`, run on a schedule by a GitHub Action.

## Getting started

```bash
npm install
npm run dev
```

Open <http://localhost:3000>. `npm run dev` automatically regenerates the search index first (via the `predev` hook).

## Writing a blog post

Add a new `.mdx` file under `content/posts/`, e.g. `content/posts/my-new-post.mdx`:

```mdx
---
title: "Your Post Title"
description: "One or two sentences for the card and SEO description."
date: "2026-09-01"
author: "Your Name"
tags: ["appsec", "cloud-security"]
severity: "high" # optional — renders a severity badge; one of critical/high/medium/low
---

Your MDX content here. Standard Markdown plus JSX if you need it.
```

The post is picked up automatically on the next build — no registry or index to update by hand. The filename (minus `.mdx`) becomes the URL slug at `/blog/<slug>`.

## News feed

`app/news/page.tsx` renders whatever is in `data/news.json`. That file is generated by:

```bash
npm run fetch-news
```

which fetches and normalizes RSS from Krebs on Security, The Hacker News, BleepingComputer, Dark Reading, SecurityWeek, and The Record (edit the `FEEDS` list in `scripts/fetch-news.mjs` to add or remove sources). Each entry links out to the original publisher — nothing is rehosted.

In production, `.github/workflows/update-news.yml` runs this script every 6 hours, commits `data/news.json` if it changed, and that push triggers the deploy workflow so the live site picks up the refresh. You can also trigger it manually from the **Actions** tab (`workflow_dispatch`).

## Search

`npm run build` (and `build-search-index` specifically) generates `public/search-index.json` from every post's frontmatter and body. `/search` fetches that file client-side and queries it with Fuse.js — no server, no API route.

## Deploying to GitHub Pages

1. Push this repository to GitHub.
2. In the repo's **Settings → Pages**, set **Source** to **GitHub Actions**.
3. Push to `main`. `.github/workflows/deploy.yml` builds the static export and deploys it.

The workflow figures out the right base path and site URL automatically:

- A repo named `<owner>.github.io` is treated as a root user/org site (`https://<owner>.github.io`).
- Any other repo name is treated as a project site served from a subpath (`https://<owner>.github.io/<repo>`), and `NEXT_PUBLIC_BASE_PATH` is set accordingly so internal links and assets resolve correctly.

### Custom domain

If you point a custom domain at the Pages site, set `NEXT_PUBLIC_BASE_PATH=""` and `NEXT_PUBLIC_SITE_URL` to your domain in the deploy workflow's `Build` step (or as repository variables), and add a `public/CNAME` file with your domain.

### Deploying elsewhere (Vercel, Netlify, etc.)

The site is a static export, so `npm run build` produces a plain `out/` directory you can host anywhere. Set `NEXT_PUBLIC_SITE_URL` (and `NEXT_PUBLIC_BASE_PATH` if not serving from the domain root) as environment variables at build time.

## Environment variables

| Variable | Purpose | Default |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | Absolute URL used in the RSS feed, sitemap, and Open Graph metadata. | `https://example.com` |
| `NEXT_PUBLIC_BASE_PATH` | Subpath the site is served from (e.g. `/my-repo` for a GitHub Pages project site). | `""` |

Both are read at build time and inlined into the static export.

## Project structure

```
app/                 Routes (App Router)
  blog/[slug]/        Individual post pages
  tags/[tag]/          Tag archive pages
  news/, search/, about/
  rss.xml/route.ts     RSS feed
  sitemap.ts, robots.ts
components/          UI components (header, footer, post cards, theme toggle, MDX renderer...)
content/posts/       Blog posts, as MDX with frontmatter
data/news.json       Aggregated news items (regenerated by scripts/fetch-news.mjs)
lib/                 Content-loading utilities (posts, news, site metadata)
scripts/             Node scripts run outside the Next.js build (news fetch, search index)
.github/workflows/   CI, scheduled news refresh, GitHub Pages deploy
```

## Scripts

| Command | Does |
|---|---|
| `npm run dev` | Start the dev server (regenerates the search index first). |
| `npm run build` | Regenerate the search index, then produce the static export in `out/`. |
| `npm run lint` | ESLint. |
| `npm run fetch-news` | Refresh `data/news.json` from the configured RSS sources. |
| `npm run build-search-index` | Regenerate `public/search-index.json` from `content/posts/`. |

## Content policy

This site is written for defenders. Posts explain how vulnerability classes and attacks work so readers can build and justify defenses, not as a how-to for attacking systems without authorization — see `app/about/page.tsx`.
